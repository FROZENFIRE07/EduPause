WHAT IS PROJECT Y?
──────────────────
GATE Mastery Engine is a lean, exam-focused study system for GATE (Graduate
Aptitude Test in Engineering) preparation. It transforms YouTube lecture videos
into structured, timestamp-indexed notes optimized for exam revision.

It is NOT a generic adaptive learning platform. It is a deterministic,
PYQ-driven content pipeline with a clean reading interface.

WHY SIMPLICITY IS PREFERRED
────────────────────────────
1. GATE aspirants need NOTES, not gamification.
2. The core value is: "Watch video → Get structured notes → Revise efficiently"
3. Every unnecessary feature is a distraction from shipping.
4. One Node.js backend + one React frontend. Zero Python. Zero Neo4j. Zero agents.
5. Ship in 2-3 weeks, not 3 months.

KEY ARCHITECTURAL DECISIONS
────────────────────────────
1. SINGLE BACKEND — No Python service. All AI calls are via Groq REST from Node.js.
2. MONGODB ONLY — No Neo4j, no Qdrant. Notes are stored as structured JSON documents.
3. NO AGENTS — Direct function calls. summarize() and generateNotes() are plain functions.
4. PIPELINE, NOT GRAPH — Linear: ingest → transcript → chunk → summarize → notes.
5. NOTES ARE THE PRODUCT — Everything exists to produce high-quality GATE notes.

```javascript
// In groqClient.js — NEW function replacing old summarizeChunk

export async function summarizeChunkGATE(chunkText, videoTitle = '', timeRange = null) {
    const timeLabel = timeRange
        ? `\nThis chunk covers video timestamps ${timeRange.startTime} to ${timeRange.endTime}.`
        : '';

    const response = await client.chat.completions.create({
        model: MODEL,
        messages: [
            {
                role: 'system',
                content: `You are an expert GATE exam prep summarizer. Given a lecture transcript chunk, produce a structured JSON summary.

Output STRICT JSON:
{
  "subject": "GATE subject (e.g., Digital Logic, OS, DBMS, CN, TOC, Algorithms, etc.)",
  "topics": ["specific topic 1", "specific topic 2"],
  "summary": "Detailed markdown summary preserving formulas, steps, theorems",
  "keyFormulas": ["formula 1 in LaTeX/plain text", ...],
  "definitions": ["Term: definition", ...],
  "examRelevance": "high | medium | low",
  "pyqHint": "How this content typically appears in GATE (or null)"
}

Rules:
- Preserve ALL formulas, derivations, and theorems EXACTLY
- Note GATE exam traps and common mistakes
- Reference timestamps when provided
- Be precise and technical — this is for engineering students`
            },
            {
                role: 'user',
                content: `Video: "${videoTitle}"${timeLabel}\n\nTranscript:\n${chunkText}`
            }
        ],
        temperature: 0.2,
        max_tokens: 1000,
        response_format: { type: 'json_object' },
    });

    const parsed = JSON.parse(response.choices[0]?.message?.content || '{}');
    return parsed;
}
```

PROMPT TEMPLATE:

```
SYSTEM PROMPT:
You are a GATE topper-level notes generator. Given structured summaries of a
lecture video, produce comprehensive, exam-ready study notes.

Your notes MUST include these sections (in this order):

1. **📋 Overview** — 2-3 line summary of the video's coverage
2. **📖 Definitions** — Every technical term defined precisely
3. **🎯 Key Points** — Numbered list of critical concepts (exam-likely)
4. **📐 Formulas & Theorems** — Every formula/theorem with conditions
5. **📝 Detailed Notes** — Timestamp-indexed detailed explanation
6. **⚠️ Common Mistakes & GATE Traps** — What students get wrong
7. **📊 PYQ Insights** — How these topics appear in GATE (question patterns)
8. **⚡ Quick Revision** — 10-15 one-liner bullet points for last-day revision
9. **🔗 Prerequisites** — What should be known before this topic
10. **📌 Summary Table** — Key comparisons in table format (if applicable)

Rules:
- Be PRECISE — this is engineering, not storytelling
- Include ALL formulas in plain text or LaTeX
- Reference video timestamps [HH:MM:SS] for each major point
- Notes should be SELF-SUFFICIENT for revision (no need to re-watch)
```

```javascript
// In groqClient.js — NEW function

export async function generateGATENotes(chunkSummaries, videoTitle) {
    // Combine all chunk summaries into a single context
    const combinedContext = chunkSummaries.map((s, i) => {
        const time = s.startTime ? `[${s.startTime} - ${s.endTime}]` : `[Chunk ${i+1}]`;
        return `${time}\n${s.summary}\nFormulas: ${(s.keyFormulas || []).join(', ')}\nDefinitions: ${(s.definitions || []).join(', ')}`;
    }).join('\n\n---\n\n');

    const response = await client.chat.completions.create({
        model: MODEL,
        messages: [
            {
                role: 'system',
                content: `You are a GATE topper-level notes generator. Given structured summaries of a lecture video, produce comprehensive, exam-ready study notes in markdown.

REQUIRED SECTIONS (use these exact headers):
## 📋 Overview
## 📖 Definitions
## 🎯 Key Points
## 📐 Formulas & Theorems
## 📝 Detailed Notes
## ⚠️ Common Mistakes & GATE Traps
## 📊 PYQ Insights
## ⚡ Quick Revision
## 🔗 Prerequisites

Rules:
- Be PRECISE. This is for engineering students preparing for GATE.
- Include ALL formulas (LaTeX or plain text).
- Reference [HH:MM:SS] timestamps for every major point.
- Notes must be SELF-SUFFICIENT (no need to re-watch the video).
- Quick Revision = 10-15 crisp one-liners for last-day revision.
- PYQ Insights = How each topic typically appears in GATE questions.
- 800-1500 words total.`
            },
            {
                role: 'user',
                content: `Generate GATE-ready notes for: "${videoTitle}"\n\nChunk Summaries:\n\n${combinedContext}`
            }
        ],
        temperature: 0.25,
        max_tokens: 3000,
    });

    return response.choices[0]?.message?.content || '';
}
```


──── 4.4 KNOWLEDGE BASE LAYER ─────────────────────────────────────────────────

SINGLE SOURCE OF TRUTH: MongoDB

There is NO knowledge graph (Neo4j) and NO vector DB (Qdrant) in Project Y.
All data lives in MongoDB as structured JSON documents.

DATA RELATIONSHIPS:

  Playlist (1) ──▶ (N) Videos
  Video    (1) ──▶ (1) Transcript
  Video    (1) ──▶ (N) ChunkSummaries
  Video    (1) ──▶ (1) Notes

Everything is linked by `videoId` and `playlistId`.

WHY THIS IS SUFFICIENT:
1. GATE prep is structured — topics are linear, not graph-shaped.
2. Notes are text documents, not vector embeddings.
3. Search can be done with MongoDB text indexes (good enough for MVP).
4. If vector search is needed later, add Qdrant post-MVP.

  5. DATA FLOW (Step-by-Step)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PIPELINE: Playlist URL → Final Notes

  STEP 1: USER INPUT
  ──────────────────
  Input:  YouTube playlist URL or single video URL
  Action: POST /api/ingest { playlistUrl: "https://youtube.com/playlist?list=..." }
  Output: { jobId: "uuid" }

          │
          ▼

  STEP 2: PLAYLIST METADATA EXTRACTION
  ──────────────────────────────────────
  Input:  Playlist URL
  Action: youtube.js → fetchPlaylistVideos()
          - Try YouTube Data API (with key rotation)
          - Fallback: scrape YouTube page HTML
  Output: Array of { videoId, title, description, position }
  Store:  → MongoDB `playlists` collection
  Status: Job marked "complete" — user can start watching immediately

          │  (background continues)
          ▼

  STEP 3: TRANSCRIPT EXTRACTION (per video, sequential)
  ──────────────────────────────────────────────────────
  Input:  videoId
  Action: youtube.js → fetchTranscript()
          Priority: yt-dlp CLI → Puppeteer → HTTP scrape → AI generation
  Output: { plainText: "full text", segments: [{start, end, startSec, endSec, text}] }
  Store:  → MongoDB `transcripts` collection
  Delay:  5-second delay between videos (rate limit respect)

          │
          ▼

  STEP 4: TIMESTAMP-AWARE CHUNKING (per video)
  ─────────────────────────────────────────────
  Input:  segments[] (from Step 3)
  Action: chunker.js → chunkWithTimestamps(segments, { chunkSize: 512 })
          - Groups VTT cues into ~512 word chunks
          - Preserves startTime/endTime per chunk
          - Falls back to chunkTranscript() if no timestamps
  Output: Array of { text, startTime, endTime, startSec, endSec }

          │
          ▼

  STEP 5: GATE-ORIENTED SUMMARIZATION (per chunk)
  ────────────────────────────────────────────────
  Input:  chunk.text + videoTitle + timeRange
  Action: groqClient.js → summarizeChunkGATE()
          - Groq API (llama-3.3-70b-versatile)
          - GATE-focused prompt (see Section 4.2)
  Output: {
            subject, topics[], summary, keyFormulas[],
            definitions[], examRelevance, pyqHint
          }
  Store:  → MongoDB `summaries` collection (per chunk)

          │
          ▼

  STEP 6: NOTES GENERATION (per video — after ALL chunks summarized)
  ──────────────────────────────────────────────────────────────────
  Input:  All chunk summaries for one video
  Action: groqClient.js → generateGATENotes()
          - Combines all chunk summaries
          - Single LLM call to produce cohesive notes
          - 10 mandatory sections (see Section 4.3)
  Output: {
            videoId, videoTitle, subject, topics[],
            notes (markdown), quickRevision[],
            formulaCount, definitionCount, estimatedGATERelevance
          }
  Store:  → MongoDB `notes` collection

          │
          ▼

  STEP 7: USER READS NOTES
  ─────────────────────────
  Frontend: GET /api/notes/:videoId
  Display:  Split-panel view — video on left, notes on right
  Feature:  Click timestamp → video seeks to that point


COMPLETE DATA FORMAT TRANSFORMATIONS:

  URL string
    → { videoId, title }[]                           (Step 2: playlist metadata)
    → { plainText, segments[] }                      (Step 3: raw transcript)
    → { text, startTime, endTime }[]                 (Step 4: chunks)
    → { summary, keyFormulas[], definitions[] }[]    (Step 5: GATE summaries)
    → { notes: "markdown", quickRevision[] }         (Step 6: final notes)

  11. WHAT NOT TO BUILD
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The following features exist in Project X and MUST NOT be included in MVP:

  ╳  Multi-Agent Orchestration (LangGraph)
     Why: Notes generation is a single LLM call, not a graph of agents.

  ╳  Python Agent Service (agent-core-py/)
     Why: All LLM calls happen via Groq REST from Node.js. No Python needed.

  ╳  Knowledge Graph (Neo4j)
     Why: GATE prep is linear (video → notes). No prerequisite mapping needed.

  ╳  Vector Database (Qdrant)
     Why: Notes are text, not embeddings. MongoDB text search is sufficient.

  ╳  Clickstream Tracking + Confusion Detection
     Why: Users are reading notes, not being monitored for confusion.

  ╳  Socratic Intervention System
     Why: No popup quizzes. Users read notes at their own pace.

  ╳  Break Recovery Protocol
     Why: Users open the app, see their notes. No cognitive priming needed.

  ╳  Mastery Scoring + Progress Tracking
     Why: Simple checkmarks (watched / not watched) replace complex mastery scores.

  ╳  Achievement System + Gamification
     Why: GATE aspirants need results, not badges. No confetti. No toasts.

  ╳  AI Roadmap Generation
     Why: The playlist order IS the roadmap. No need for AI-generated milestones.

  ╳  Quiz System (30-question quizzes)
     Why: Notes + PYQ insights replace quiz generation. Build PYQ bank post-MVP.

  ╳  Next-Step Recommendations
     Why: "Watch the next video" is the recommendation.

  ╳  Onboarding Flow
     Why: Import URL → Get notes. That's the onboarding.

  ╳  Authentication
     Why: MVP is single-user. Local storage is sufficient.

  ╳  Semantic Search
     Why: Ctrl+F on notes. Post-MVP feature if needed.

  ╳  Spaced Repetition
     Why: Quick Revision bullets serve this purpose for now.

  ╳  Knowledge Graph Visualization (vis-network)
     Why: No graph, no visualization.

  ╳  AI Chat Tutor
     Why: Notes are the tutor. Post-MVP feature.

  ╳  Theater Mode
     Why: Unnecessary complexity for a study app.

  APPENDIX B: MODIFIED INGESTION PIPELINE (pseudocode)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

async function runIngestionPipeline(jobId, playlistUrl) {
    // PHASE 1: FAST PATH (same as Project X)
    const videos = await fetchPlaylistVideos(playlistUrl);
    job.status = 'complete';  // User can start watching immediately
    saveToDB('playlists', { playlistUrl, videos });

    // PHASE 2: BACKGROUND (modified from Project X)
    job.bgStatus = 'processing';

    // Step 2: Extract transcripts (SAME as Project X)
    for (const video of videos) {
        await delay(5000);
        const { plainText, segments } = await fetchTranscript(video.videoId);
        saveToDB('transcripts', { videoId, plainText, segments });
    }

    // Step 3: Chunk + Summarize (MODIFIED — GATE prompts)
    for (const video of transcripts) {
        const chunks = chunkWithTimestamps(video.segments, { chunkSize: 512 });
        const summaries = [];

        for (const chunk of chunks) {
            const summary = await summarizeChunkGATE(chunk.text, video.title, {
                startTime: chunk.startTime,
                endTime: chunk.endTime
            });
            summaries.push({ ...summary, chunkIndex, startTime, endTime });
            saveToDB('summaries', summary);
        }

        // Step 4: Generate Notes (NEW — does not exist in Project X)
        const notes = await generateGATENotes(summaries, video.title);
        saveToDB('notes', { videoId, videoTitle, notes, subject, topics... });
    }

    // REMOVED: Step 4 (extractConcepts → Neo4j)
    // REMOVED: Step 5 (embedBatch → Qdrant)

    job.bgStatus = 'complete';
}
